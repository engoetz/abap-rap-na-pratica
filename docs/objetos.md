# Objetos do pacote ZCHM

Todos os objetos do repositório, na ordem em que aparecem no curso.

| Objeto | Tipo | Aula em que nasce | Para que serve |
|---|---|---|---|
| `ZCHM` | Pacote | 00.5 | Pacote do app Gestão de Chamados; todos os objetos do curso ficam nele |
| `ZCHM_DEMO` | Tabela | 01.5 | Tabela de demonstração usada como entrada do assistente *Generate ABAP Repository Objects*; não faz parte do app de chamados |
| `ZCHM_CHAMADO` | Tabela | 02.1 | Tabela de chamados: chave UUID, número legível, dados do chamado e os cinco campos administrativos |
| `ZCL_CHM_CARGA` | Classe | 02.2 | Carga de dados de teste: apaga as tabelas e grava os três chamados do curso e, a partir da 07.1, os quatro apontamentos; executa com F9 (`if_oo_adt_classrun`) |
| `ZR_Chamado` | CDS view entity (raiz) | 02.3 | View base do business object: lê `zchm_chamado` e dá os nomes de negócio aos campos; a partir da 07.1 declara a composição `_Apontamentos` |
| `ZI_ClienteVH` | CDS view entity | 02.4 | Ajuda de pesquisa de clientes: código e nome, lidos da view padrão `I_Customer` |
| `ZCHM_STATUS` | Domínio | 02.4 | Valores fixos do status do chamado: `A` Aberto, `E` Encerrado |
| `ZI_StatusVH` | CDS view entity | 02.4 | Ajuda de pesquisa de status: lê os valores fixos do domínio `ZCHM_STATUS` |
| `ZCHM_PRIORIDADE` | Domínio | 02.4 (exercício) | Valores fixos da prioridade: `A` Alta, `M` Média, `B` Baixa |
| `ZI_PrioridadeVH` | CDS view entity | 02.4 (exercício) | Ajuda de pesquisa de prioridade: lê os valores fixos do domínio `ZCHM_PRIORIDADE` |
| `ZC_Chamado` | CDS projection view (raiz) | 03.1 | Projeção de `ZR_Chamado` para o app de suporte, com `provider contract transactional_query`; a partir da 07.1 redireciona `_Apontamentos` para `ZC_Apontamento`; a partir da 11.1 tem o virtual element `DiasEmAberto`, calculado pela classe `ZCL_CHM_VE_DIAS` |
| `ZUI_CHAMADO` | Service definition | 03.2 | Diz o que entra no serviço: expõe `ZC_Chamado` com o nome público `Chamado`; a partir da 07.3 expõe também `ZC_Apontamento` como `Apontamento`; a partir da 11.2 expõe a custom entity `ZCE_SlaChamado` como `SlaChamado` |
| `ZUI_CHAMADO_O4` | Service binding (OData V4 - UI) | 03.2 | Publica `ZUI_CHAMADO` como OData V4 de UI e libera o preview do app; depois do pull é preciso publicar (botão *Publish*); a partir da 11.2 traz também a entidade `SlaChamado`; é o serviço que o app Fiori da 12.3 consome |
| `ZC_Chamado` | Metadata extension | 03.3 | Anotações de tela da projeção: colunas, filtros e cabeçalho da lista; seções da object page a partir da 03.4; seção com a tabela de apontamentos a partir da 07.3; coluna "Dias em aberto" a partir da 11.1 |
| `ZCHM` | Classe de objetos de autorização | 03.6 | Agrupa os objetos de autorização do app |
| `ZCHM_CLI` | Campo de autorização | 03.6 | Campo de cliente (elemento de dados `KUNNR`) usado no objeto de autorização `ZCHM_CLI` |
| `ZCHM_CLI` | Objeto de autorização | 03.6 | Cliente (`ZCHM_CLI`) e atividade (`ACTVT`, 03 = exibir); o papel de cada usuário na PFCG diz quais clientes ele enxerga |
| `ZR_Chamado` | Access control (DCL) | 03.6 | Só passa a linha cujo cliente está na autorização `ZCHM_CLI` do usuário |
| `ZC_Chamado` | Access control (DCL) | 03.6 | A projeção herda as condições de `ZR_Chamado` (`inheriting conditions from entity`) |
| `ZR_Chamado` | Behavior definition (managed) | 04.1 | Comportamento do business object: `create`, `update`, `delete`, chave UUID gerada pelo framework, campos somente leitura e o mapping para `zchm_chamado`; com draft a partir da 05.2; `authorization master ( global, instance )` a partir da 09.2 e `update ( precheck )` a partir da 09.4; `with additional save with full data` na 10.2; na 10.3 sai o `persistent table` do chamado e entra `with unmanaged save with full data`; a partir da 07.2 traz também o bloco do filho `ZR_Apontamento` (alias `Apontamento`), criado pela associação `_Apontamentos`; a function estática `ResumoChamados` entra na 11.3; o business event `ChamadoEncerrado` na 11.4; na 11.5 fica extensível: `extensible` no cabeçalho (validações no save e determinações), na entidade do chamado e na action `Prepare` |
| `ZBP_R_CHAMADO` | Classe (behavior pool) | 04.1 | Onde mora a lógica do business object; classe local handler `lhc_Chamado`; até o M05 só com o método de autorização vazio, no M06 ganha as determinations, validations, actions e o feature control; a autorização global (`get_global_authorizations`) entra na 09.2 e a de instância (só o responsável ou o gestor encerra) na 09.3; o precheck do update (`precheck_update`, prioridade Alta só para o gestor) na 09.4; a classe local saver `lsc_ZR_Chamado` entra na 10.1, com `finalize` e `check_before_save` redefinidos só para o depurador ter onde parar; na 10.2 a saver ganha o `save_modified`, que grava o log em `zchm_log`; na 10.3 o `save_modified` passa a entregar os chamados à classe legada `ZCL_CHM_LOG_LEGADO`; a partir da 07.5 tem também a classe local `lhc_Apontamento` (total de horas e, na 07.6, as validações do filho); na 11.3 o handler ganha o método da function `ResumoChamados` (`FOR READ`); na 11.4 o `save_modified` dispara o evento `ChamadoEncerrado` (`RAISE ENTITY EVENT`) para os chamados cujo status passou a `E` naquele save; é o behavior pool exercitado pelos testes de `ZCL_CHM_TESTE_CHAMADO` (módulo 12) |
| `ZC_Chamado` | Behavior definition (projeção) | 04.1 | Expõe ao serviço, com `use`, as operações definidas na BDEF base; a partir da 07.2 inclui o bloco de `ZC_Apontamento` e `use association`; `use function ResumoChamados` a partir da 11.3 |
| `ZCHM_CHAMADO_D` | Tabela (draft) | 05.2 | Tabela de rascunho de `ZR_Chamado`: um campo por elemento da view, com os nomes da CDS, mais o include administrativo `sych_bdl_draft_admin_inc`; gerada pelo ADT (Ctrl+1 na BDEF), nunca editada à mão |
| `ZCHM_MSG` | Classe de mensagens | 06.4 | Textos das mensagens do app: 001 título obrigatório, 002 cliente inexistente; a 003 (motivo do encerramento) entra na 06.6; 010 (horas maiores que zero) e 011 (data não futura) entram na 07.6; 020 (prioridade Alta só para o gestor) na 09.4 |
| `ZA_MotivoEncerramento` | CDS abstract entity | 06.6 | Estrutura do parâmetro da action `encerrarComMotivo`: um campo, `Motivo`; o Fiori elements monta o diálogo a partir dela |
| `ZCHM_APONT` | Tabela | 07.1 | Tabela de apontamentos de horas: chave UUID própria, `chamado_uuid` com a chave do chamado (pai), data, horas, descrição e os cinco campos administrativos; já vem pronta na aula |
| `ZR_Apontamento` | CDS view entity (filho) | 07.1 | View base do apontamento: lê `zchm_apont` e aponta para o chamado com `association to parent` |
| `ZC_Apontamento` | CDS projection view (filho) | 07.1 | Projeção de `ZR_Apontamento` para o app; `_Chamado` redirecionada para `ZC_Chamado` |
| `ZCHM_APONT_D` | Tabela (draft) | 07.2 | Tabela de rascunho de `ZR_Apontamento`, gerada pelo ADT (Ctrl+1 na BDEF); a aula 07.4 abre a tabela e explica o `with draft` das associações |
| `ZC_Apontamento` | Metadata extension | 07.3 | Anotações de tela do apontamento: colunas da tabela dentro do chamado (`@UI.lineItem`) e campos da página de detalhe (`@UI.identification`) |
| `ZCL_CHM_EML_DEMO` | Classe | 08.1 | Classe de console do módulo de EML (`if_oo_adt_classrun`, executa com F9): o método `main` é reescrito a cada aula do M08 — leitura (08.1), tipos derivados (08.2), create e update (08.3), create by association e deep create (08.4), actions (08.5), commit com tratamento de erro (08.6) e a prova do `IN LOCAL MODE` (08.7) |
| `ZCHM_CHAM` | Objeto de autorização | 09.2 | Autorização de escrita do app, só com o campo de atividade `ACTVT`: 01 = criar, 06 = excluir, 70 = administrar (o gestor); na gravação o objeto, os papéis e o usuário de teste `ANALISTA` são tarefa de Basis — o objeto vem no repositório, os papéis (PFCG) não |
| `ZCHM_LOG` | Tabela | 10.2 | Log de alteração do chamado: chave UUID própria, UUID do chamado, operação (`C` criação, `U` alteração, `D` exclusão), status naquele momento, usuário e hora (`utclong`); já vem pronta na aula; gravada pelo `save_modified` na 10.2 e pela classe legada a partir da 10.3; a partir da 11.4 recebe também a operação `E`, gravada pelo handler do evento `ChamadoEncerrado` |
| `ZCL_CHM_LOG_LEGADO` | Classe | 10.3 | Código do curso que faz o papel do legado: `gravar` regrava os chamados em `zchm_chamado` e insere uma linha por chamado em `zchm_log`; `excluir` apaga o chamado e registra a operação `D`; não faz `COMMIT WORK`; preenche a chave UUID e os campos administrativos quando chegam vazios (caso do BO unmanaged das aulas 10.4 a 10.7); já vem pronta na aula |
| `ZR_ChamadoU` | CDS view entity (raiz) | 10.4 | View raiz do business object unmanaged de exemplo: lê a mesma `zchm_chamado`, com poucos campos e o número do chamado (`ChamadoID`) como chave; já vem pronta na aula |
| `ZR_ChamadoU` | Behavior definition (unmanaged) | 10.4 | Comportamento do BO unmanaged: `create`, `update`, `delete`, `lock master`, sem `persistent table`, com o mapping para `zchm_chamado`; `late numbering` a partir da 10.7 |
| `ZBP_R_CHAMADOU` | Classe (behavior pool) | 10.4 | Behavior pool do BO unmanaged: handler `lhc_Chamado` (`create`, `update`, `delete`, `read`, `lock`) e saver `lsc_ZR_ChamadoU`; nasce com todos os métodos vazios; na 10.5 o `save` e o `cleanup` passam a chamar o buffer; na 10.6 os cinco métodos do handler são preenchidos (CRUD completo, leitura pelo buffer e bloqueio com `EZCHM_CHAMADO`); na 10.7 o `create` devolve um `%pid` e a saver ganha o `adjust_numbers` (late numbering) |
| `ZCL_CHM_TESTE_U` | Classe | 10.4 | Classe de console (`if_oo_adt_classrun`, executa com F9) que testa o BO unmanaged por EML; o método `main` muda a cada aula, da 10.4 à 10.7 |
| `ZCL_CHM_BUFFER` | Classe | 10.5 | Buffer transacional do BO unmanaged, só com métodos estáticos: guarda o que foi criado, alterado e excluído na interaction phase (`incluir`, `alterar`, `excluir`), responde às leituras olhando a memória antes do banco (`ler`), entrega tudo à classe legada no `save` (`gravar`) e se esvazia no `cleanup` (`limpar`); na 10.7 ganha `novo_uuid` e `numerar` (número definitivo no `adjust_numbers`) e passa a achar pelo `%pid` os chamados criados na transação |
| `EZCHM_CHAMADO` | Objeto de bloqueio | 10.6 | Bloqueio clássico (enqueue) da tabela `zchm_chamado`, com o argumento `CHAMADO_UUID`; usado pelo método `lock` do BO unmanaged; já vem pronto na aula |
| `ZCL_CHM_VE_DIAS` | Classe | 11.1 | Calcula o virtual element `DiasEmAberto` de `ZC_Chamado` (`if_sadl_exit_calc_element_read`): `get_calculation_info` pede `CreatedAt` e `Status`, `calculate` devolve os dias desde a criação para os chamados abertos |
| `ZCE_SlaChamado` | CDS custom entity | 11.2 | Prazo de atendimento (SLA) de cada chamado: tem chave e campos, mas não tem `SELECT`; os dados vêm da classe `ZCL_CHM_SLA_QUERY`; as anotações de tela ficam nos próprios campos |
| `ZCL_CHM_SLA_QUERY` | Classe | 11.2 | Classe de consulta da custom entity (`if_rap_query_provider`): o método `select` devolve três linhas fixas, no lugar da chamada à API externa de SLA, e responde ao que o request pede — filtro, ordenação, paginação, dados e contagem |
| `ZA_ResumoChamados` | CDS abstract entity | 11.3 | Formato da resposta da function `ResumoChamados`: `Abertos`, `Encerrados` e `HorasTotais` |
| `ZCL_CHM_EVT_CHAMADO` | Classe (event handler) | 11.4 | Ouve os business events de `ZR_Chamado` (`FOR EVENTS OF`); a classe local `lhe_chamado` reage ao evento `ChamadoEncerrado` depois do commit, em outra transação, e grava em `zchm_log` uma linha com a operação `E` — o lugar onde entraria o e-mail, o faturamento ou a chamada de API |
| `ZX_CHAMADO` | Behavior definition (extension) | 11.5 | BDEF extension de `ZR_Chamado`, no papel de outro time (a filial): acrescenta a validation `zzExigirDescricao` (prioridade Alta exige descrição) e a inclui na `Prepare`, sem alterar a BDEF original |
| `ZBP_X_CHAMADO` | Classe (behavior pool) | 11.5 | Classe de implementação da extension `ZX_CHAMADO`: handler local com o método da validation `zzExigirDescricao` |
| `ZI_ChamadoTP` | CDS projection view (interface) | 11.6 | Interface do BO para outros programas: projeção de `ZR_Chamado` com `provider contract transactional_interface` e só os campos oferecidos para fora (sem a descrição e sem os campos administrativos); na aula é liberada com o contrato C1 pela aba *API State* do ADT — depois do pull, faça essa liberação à mão |
| `ZI_ChamadoTP` | Access control (DCL) | 11.6 | A interface herda as condições de `ZR_Chamado` |
| `ZI_ChamadoTP` | Behavior definition (interface) | 11.6 | Interface BDEF: oferece `create`, `update` e a action `encerrar`; não oferece `delete`; também liberada com C1 na aula |
| `ZCL_CHM_INTEGRACAO` | Classe | 11.6 | Classe de console (`if_oo_adt_classrun`, executa com F9) no papel do programa de outro time: cria um chamado por EML pela interface `ZI_ChamadoTP`; na aula ela começa apontando para `ZR_Chamado` e é trocada para a interface |
| `ZAPI_CHAMADO` | Service definition | 11.7 | Serviço da API de integração, separado do serviço da tela: expõe `ZC_Chamado` como `Chamado` e `ZC_Apontamento` como `Apontamento` |
| `ZAPI_CHAMADO_O4` | Service binding (OData V4 - Web API) | 11.7 | Publica `ZAPI_CHAMADO` como OData V4 de Web API, para outros sistemas (sem preview); depois do pull é preciso publicar |
| `ZCL_CHM_TESTE_CHAMADO` | Classe (teste ABAP Unit) | 12.1 | Testes automáticos do BO de chamados, por EML (`FOR TESTING`, roda com Ctrl+Shift+F10): `sem_titulo_nao_grava` prova que a validation barra o chamado sem título no `COMMIT ENTITIES`; `teardown` faz `ROLLBACK ENTITIES` depois de cada teste; a partir da 12.2 os testes rodam contra dublês de CDS (`cl_cds_test_environment`, criados no `class_setup`, limpos no `setup`, destruídos no `class_teardown`), sem tocar nas tabelas reais, e a classe ganha o teste `encerrar_muda_status` |
| `ZCHM_CHAMADOS` | Aplicação BSP (app Fiori) | 12.4 | O app Fiori elements depois do deploy (`npm run deploy`): aparece no pacote, na pasta *BSP Library*. **Não vem no repositório** — é criado no seu sistema pelo deploy do projeto gerado na aula 12.3; o passo a passo está em [`ui/chamados/README.md`](../ui/chamados/README.md). O catálogo `ZCHM_CAT` e a função `ZCHM_ATENDENTE` também são criados à mão |
